# Phrase-tree quiz questions

The quiz topic "Shared Quranic wording" (`BRANCHES`, متشابهات القرآن) asks about the word trees on `/quran/branches`. A question shows wording shared by several ayat, wherever it occurs, and asks what follows in each branch. The quiz uses the same tree inventory and formation rules as the explorer, then applies quiz-suitability rules before asking for selected leaves.

## Questions (`branchQuestions` in `src/lib/quiz/branchQuestions.ts`)

- The questions come from `src/app/quran/branches/trees.json` through `buildTreeGroups`, so the explorer and quiz use the same tree inventory. Nothing is stored separately for the quiz.
- A question accepts 2–10 distinct ayat and 2–10 branches at the first split. It carries the complete tree after the shared phrase and the words preceding that phrase in each ayah. Empty prefixes are omitted; they do not request a previous ayah. A tree is left out when an ayah ends at the shared phrase or when it does not split. The explorer's separate `PIECE_MAX` limit does not constrain quizzes.
- Where the ayat of a piece open with different first words, with or without a leading و or ف or with a different lemma, the prompt names each spelling, such as «يَطُوفُ عَلَيْهِمْ» أو «وَيَطُوفُ عَلَيْهِمْ» or «وَإِنَّ» أو «وَإِن», and the tree draws each spelling as its own node before the shared words, as `/quran/branches` does. In the quiz these nodes carry no link, since the spelling's own tree would show the answers. After checking, each ayah carries its spelling beside its reference.
- The setup takes a juz' range (`juzFrom` and `juzTo`, 1 to 30, default all). The ayat outside it are dropped before the tree is built, so the reader answers only the branches inside the range. In juz' 29 to 30, فلا أقسم has four branches (69:38, 70:40, 81:15, 84:16), and 56:75 in juz' 27 is not asked for. The range applies to this topic only.
- `juzOf` in `src/lib/quran/juz.ts` places an ayah by the 30 ayat each juz' starts at. A page lookup would be wrong for juz' 4, 7, 11 and 26, whose first ayah (3:93, 5:82, 9:93, 46:1) falls mid-page.
- These questions skip the reviewed bank under `data/quiz/`. The answer is the Quran text itself, and there is no distractor to check.
- The topic can be combined with the bank topics in one quiz, a person's circle included. A person's circle adds that person's questions to the other topics chosen beside it.
- Solo and party setup take the number of answers per tree (`leaves`, 1 to 10, default 3; 1 is labelled easy and 10 hard). `askedNodes` picks that many leaves at random for each question, and every other node is shown already filled in. A tree with fewer leaves asks for all of them. A question without `asked` asks every node, as before.
- The setup draws a real tree from the pool (`src/app/quizzes/example.json`, the قال piece, checked against the pool by a test) with the asked leaves as empty boxes, and states the grading rule and the meaning of the amber button and the green and purple first words.

## Grading (`matchTreeAnswers` in `src/lib/quiz/branchAnswers.ts`)

- Each non-root node has one slot, in the tree's depth-first order. A given node's slot holds its own words and is fixed to that node, so only asked leaves can swap with each other. Checking is available after typing in any field and shows corrections for blank nodes. A question counts as correct only when every field is correct, but the score gives one point for each correct asked leaf (other question kinds score one point each). A node that splits again needs all its words. A leaf needs at least its first two words, or all of them if it has fewer, because siblings always differ at their first word and the full ayah is a typing test on a phone. Every word typed must still be right and in order, so a skipped or misspelled word fails the leaf wherever it falls (جاهد الكفار واغلظ skips والمنافقين). Filling only the first split or leaving a leaf blank does not complete the tree.
- Sibling branches with the same shape can be entered in either order. Grading pairs whole subtrees, so a leaf must remain under its parent. Each expected subtree is used once. Feedback uses the pairing with the most correct nodes and, among those, the one whose answers get the most words right from the start, so a wrong answer is shown beside the leaf it starts like. It displays the correct text at every node, and links terminal ayat to their reader pages.
- After checking, every leaf offers an ayah-context overlay. A filled amber button also identifies nodes with differing marks. Context controls stay hidden while answering. See [ADR 0034](adr/0034-one-inventory-defines-quran-branch-trees.md).
- Inputs show only the supplied shared wording and the tree's shape. Answer words, surah labels and reader links appear after checking.
- The reader writes ordinary Arabic spelling, not the mushaf rasm. Each rasm word is turned into a pattern of the spellings a reader may use, and a typed answer must match it letter for letter after `normalizeWord`:
  - A dagger alif may be written or left out, so السماوات and الكتاب match, and so do هذا, ذلك and إله.
  - A waw or ya that only carries a dagger alif may be written as that alif, so الصلاة, الحياة and التوراة match.
  - A hamza may be written on any seat, alif included, or left out, so شيئا, آمنوا, امنوا and أرأيتم match. A hamza on ya or waw may use the bare keyboard letter, so يوميذ and يومئذ match, and يومنون matches يؤمنون. شي matches شَىْءٍ.
  - A small waw or ya in the rasm may be written as a full letter, so النبيين, إبراهيم and يستوون match.
  - An alif the rasm writes may not be dropped, and nothing else is loosened, so قل does not match قَالَ and لا does not match إِلَىٰ.
- An answer is read from its start and must stop at the end of a word. Spaces are ignored, so يا أيها matches يَـٰٓأَيُّهَا. There is no general edit-distance matching, so changing an unrelated consonant still fails.
- Words with the same letters, root and lemma share one node, as on the page, so the reader never types تتخذوا into two sibling fields for تَتَّخِذُوا۟ and تَتَّخِذُوٓا۟. Sibling fields with the same letters remain only where the lemmas differ, such as إِن and إِنَّ, and grading pairs them by what follows.
- A ﴿n﴾ marker that carries an ayah into the next one is shown but not typed.
- Answers typed but not checked are graded when the quiz is submitted.
- After checking, the solution tree shows numbered verdicts, typed corrections and the correct Quran text, with the words needed for a complete answer underlined. The surrounding-ayat toggle appears only with the solution, starts off and loads context when enabled. There is no separate phrase-tree navigation button. While a quiz runs the site footer is hidden.
